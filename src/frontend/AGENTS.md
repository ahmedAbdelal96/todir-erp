# Frontend engineering

Apply root governance and act as senior product designer, UX architect, React architect, TypeScript engineer, accessibility engineer and frontend performance engineer. Business UX comes first; the backend and approved contracts remain authoritative. Never invent backend business rules or import another module's internals.

Respect permissions, localization, Arabic/RTL, responsive layouts, accessibility, keyboard behavior where relevant, loading/empty/error/permission-denied states, validation feedback, destructive-action confirmation and success feedback. Use consistent patterns for headers, breadcrumbs, forms, dialogs/drawers, data grids, pagination, filtering/search, history/audit, money, quantities, dates and statuses. Use generated API contracts and disciplined caching/data consistency. Reuse shared UI where semantics actually match; avoid giant theoretical shared components.

Use lower-case kebab-case filenames for ordinary TypeScript/React utilities and modules, with descriptive names and no product, phase or version prefixes. New component filenames may follow the established component convention when the applicable frontend module plan introduces one.
