## Correction delta

- Inventory status changes used by Quality now cross a typed `IInventoryQualityCapabilities` contract with an owner idempotency key and persisted owner execution state; Quality does not silently release a failed owner operation.
- Receiving resolution is per purchase-order line and fails closed when the Quality capability is unavailable. Inspection creation is fail-closed for non-AdHoc events without an effective plan.
- Result entry now rejects characteristics outside the frozen plan, duplicate sample/characteristic results, missing required evidence, invalid UOM and uncalibrated instruments; completion cannot pass with no results.
- Dispositions now require an explicit approval transition before execution; Accept/UseAsIs/Concession releases the linked Inventory restriction through the owner capability, while unsupported owner decisions fail closed. Owner execution is claimed/recoverable and partial release is quantity-conserving.
- Disposition owner capabilities now cover Inventory Scrap, Purchasing Supplier Return and Manufacturing Rework with durable owner operation evidence; Quality never fabricates a completed owner result.
- Supplier Return no longer calls Quality release before Purchasing completes the physical return. Purchasing invokes Inventory with the `QualityHold` source status, and Quality resolves its restriction only after the owning operation is confirmed; deterministic Purchasing failure leaves the restriction active.
- Unknown disposition outcomes are retryable through the authorized `POST /api/v1/quality/dispositions/{id}/reconcile` route. The persisted owner idempotency identity is reused, successful owner operations replay without duplication, and deterministic invalid requests remain `Failed` rather than `Executed`.
- Release operations are durable per idempotency key, retryable after `Unknown`, and reserve in-flight quantity while competing requests are running so concurrent owner calls cannot oversell a restriction.
- Plans, sampling plans and all operational Quality lists use typed keyset pages (`items`, `nextCursor`) with stable cursors and a server cap of 100.
- Inspection source fingerprints are unique per tenant and duplicate requests return the original inspection. Plan conflicts, explicit plan applicability, result UOM/sample/calibration/evidence and effective-date rules fail closed.
- Added typed read APIs for restrictions, dispositions, issues, NCRs, CAPA, supplier profiles, SCARs, certificates, characteristics and sampling plans; CAPA action/root-cause/effectiveness and SCAR response/review lifecycles are persisted.
- Seed verification corrected Quality references to actual Catalog/Purchasing rows; current local validation reports zero invalid product or plan-version references.
- Real-stack QA evidence: `QualityBackendAcceptanceTests` passed 15/15 against disposable local `todir_quality_targeted` after the targeted safety closure. QA-11 uses the real Purchasing receipt service and proves mandatory QualityHold; QA-12 proves supplier Return consumes QualityHold without Available leakage and replays exactly once; QA-13 proves Unknown reconciliation; QA-14 proves Purchasing failure leaves the restriction active. The existing QA-01/03/04/08/10 paths remain included, with QA-10 proving the real RabbitMQ/Worker/Inbox replay.
