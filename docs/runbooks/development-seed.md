# Development seed runbook

The canonical local ERP dataset is owned by `backend/DbMigrator/SeedData/`. It is development infrastructure, not production reference data and not a migration. It is intentionally explicit and never runs when the API starts.

## Run

After PostgreSQL is available and migrations can connect, set the local development seed credentials in the ignored shared file `backend/appsettings.Development.json`:

```powershell
{
  "Seed": {
    "DefaultPassword": "<local password: 8-128 chars, upper, lower, number>",
    "Mfa": {
      "ProtectedSecret": "",
      "RecoveryCodeDigests": ""
    }
  }
}
```

Run with `DOTNET_ENVIRONMENT=Development` so the migrator loads `backend/appsettings.Development.json` beside the shared connection string. The command runs the ordered migrations first, then explicitly seeds the two canonical tenants. It can be rerun safely. It prints canonical login email addresses, counts, and whether optional MFA material was seeded; it never prints passwords, MFA secrets, recovery codes, or tokens.

The command is rejected when `DOTNET_ENVIRONMENT`/`ASPNETCORE_ENVIRONMENT` is missing, `Production`, or another unsupported value. MFA is not guessed or generated by the migrator. To seed an MFA account, provide compatible development-only protected material through `Seed:Mfa:ProtectedSecret` and comma-separated `Seed:Mfa:RecoveryCodeDigests`; otherwise the canonical MFA scenario remains explicitly unseeded.

The canonical accounts are `admin@atlas.com` and `admin@delta.com`, with the password supplied through `Seed:DefaultPassword`. Do not commit that value.

## Verification

Run the command twice and compare the summaries and tenant-scoped counts. Use normal API authentication with each administrator, then verify Atlas and Delta list only their own Identity, Directory, Catalog, and FinanceBase data. Empty states are tested with a zero-result search; the canonical dataset is not deleted to manufacture an empty tenant.
