# Identity and sessions

Identity is global; membership is tenant-scoped; Employee belongs to HR and is not part of the Kernel. The browser authentication flow accepts only email and password initially, then returns a short-lived server-persisted challenge for MFA and/or organization selection when required. Active organizations are resolved from the identity's current memberships and tenant status; the client never supplies a tenant as an authority input. Browser sessions use secure, HttpOnly, SameSite cookies. Passwords use PBKDF2 with a per-password salt, failed-password lockout is enforced in the global identity record, and session revocation is checked before authorization through the identity security stamp. MFA uses TOTP with encrypted-at-rest secret material and one-time recovery-code digests; enabled identities must provide a valid challenge-bound code. Authentication challenges persist only a SHA-256 token digest, identity, next step, expiry, attempt count, and consumption state; they contain no password, MFA secret, or tenant authorization data. The session revocation endpoint invalidates existing cookies by rotating the security stamp. OAuth/OIDC integrations use authorization code with PKCE; access tokens are never stored in browser local storage.
