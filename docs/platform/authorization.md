# Authorization

Modules own their permission catalog through manifests. Roles contain permission entries and the tenant-bound authorization subject receives roles at Tenant, Legal Entity, or Branch scope. Backend authorization is authoritative; frontend checks only shape navigation and affordances. The permission authorizer deliberately keeps no process-wide decision cache: each request evaluates the freshly loaded PostgreSQL subject so role, assignment, lifecycle, and revocation changes cannot remain effective because of stale authorization state. Request-scoped subject reuse is limited to the current HTTP request and tenant/membership pair.
